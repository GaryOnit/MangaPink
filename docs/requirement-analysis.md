## 1. 需求背景与目标

### 1.1 项目背景

随着二次元文化在国内年轻群体中持续渗透，漫画阅读已成为核心娱乐方式之一。市面上现有漫画平台（快看漫画、哔哩哔哩漫画、腾讯动漫等）普遍存在广告干扰多、UI 风格偏向通用化、离线体验差等问题，难以满足深度二次元爱好者对沉浸式阅读体验的追求。

萌漫（MangaPink）旨在打造一款垂直于二次元领域、视觉风格鲜明的纯前端漫画阅读客户端。当前处于**原型阶段**，重点验证核心交互与视觉体验，所有资源均通过本地静态文件提供。

### 1.2 核心目标

| 目标维度 | 描述 |
|---------|------|
| 视觉体验 | 粉白甜美二次元风格 UI，首页、书架、分类页视觉打磨完成 |
| 阅读体验 | 基于 FlatList 的条漫长滚动阅读器，滚动流畅无卡顿 |
| 数据持久化 | 通过 Redux 本地持久化实现用户书架、追漫历史与阅读进度记录 |
| 工程基础 | React Native + TypeScript + NativeWind 技术栈落地，为后续后端接入铺路 |

### 1.3 成功标准

- [ ] 首页、书架、分类三大页面 UI 还原度高，视觉风格统一（粉白色调）
- [ ] 条漫阅读器在 100 张图片连续滚动场景下无明显掉帧（目标 ≥ 60fps）
- [ ] 用户阅读进度与书架数据在 App 重启后可正确恢复
- [ ] 工程代码具备可扩展性，可在后续阶段接入真实后端与网络请求

## 6. 技术可行性评估

### 6.1 技术栈选型

| 技术 | 版本建议 | 可行性 | 备注 |
|------|---------|--------|------|
| React Native | 0.74+ | ✅ 高 | 新架构（Fabric/JSI）默认开启，性能优越 |
| TypeScript | 5.x | ✅ 高 | RN 官方支持，工程规范基础 |
| NativeWind | 4.x | ✅ 高 | 基于 Tailwind CSS v3，与 RN 0.74 兼容性良好 |
| Redux Toolkit | 2.x | ✅ 高 | 官方推荐方案，搭配 RTK Query 可平滑扩展 |
| Redux Persist | 6.x | ✅ 高 | AsyncStorage 适配器成熟稳定 |
| React Navigation | 6.x | ✅ 高 | 底部 Tab + Stack 导航标准方案 |

### 6.2 关键技术点可行性

**条漫 FlatList 长滚动**
- `FlatList` 内置虚拟化，`windowSize`、`maxToRenderPerBatch`、`initialNumToRender` 可精细调控
- 建议配合高性能图片库替代原生 `Image`，提升图片解码性能。注意：`react-native-fast-image` 长期未维护（末次更新 2022 年），对 RN 新架构（Fabric）支持有限；推荐使用 `expo-image`（Expo 官方维护，支持新架构）或 `@d11/react-native-fast-image`（社区维护的新架构兼容 fork）
- **结论**：✅ 完全可行，社区有大量最佳实践可参考，注意图片库选型

**NativeWind 样式方案**
- NativeWind v4 编译时将 Tailwind 类名转换为 StyleSheet，性能接近原生
- 粉色系色板可通过 `tailwind.config.js` 自定义扩展
- **结论**：✅ 可行，需注意部分 Tailwind 类在 RN 无效（如 `display: grid`），但布局场景覆盖充分

**Redux 持久化**
- Redux Toolkit + Redux Persist + `@react-native-async-storage/async-storage` 组合成熟
- 按 slice 分级持久化，避免全量数据序列化开销
- **结论**：✅ 可行，方案稳定，社区文档完善

### 6.3 风险点

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| NativeWind v4 与 RN 新架构兼容问题 | 中 | 锁定版本，参考官方 migration guide |
| 大量本地图片导致包体积过大 | 低 | 压缩图片（WebP 格式），控制 mock 图片总量 < 20MB |
| FlatList 在低端 Android 设备掉帧 | 中 | 开启 `removeClippedSubviews`，使用 `InteractionManager` 延迟非关键渲染 |
| AsyncStorage 数据结构变更兼容 | 低 | 设计 migration 机制，版本号管理持久化 schema |
